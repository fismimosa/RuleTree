RuleTree.base.RuleTreeBaseSplitter.RuleTreeBaseSplitter#

class RuleTreeBaseSplitter[source]#

Bases: BaseEstimator, ABC

Abstract base class of the splitters, the component of a stump that finds the best split of a feature matrix: a threshold on a numerical feature (x <= threshold goes to the left child) or a value of a categorical feature (x == value goes to the left child).

A new splitter implements fit(), which sets the attributes below; apply(), get_state() and set_state() work for any split of this form. Splitters are scikit-learn estimators: their parameters are the arguments of __init__.

Variables:

  • task (str) – Kind of target: MODEL_TYPE_CLF (classification) or MODEL_TYPE_REG (regression). Class attribute.

  • feature (int) – Column of the matrix used by the split.

  • threshold (float or object) – Threshold (numerical split) or value (categorical split).

  • is_categorical (bool) – Whether the split is categorical.

  • gain (float) – Gain of the split: the stumps with the highest gain are chosen with stump_selection=’best’.

  • impurity (list of float or None) – Impurity of the node and of the two children, if computed.

See also

RuleTreeBaseGainSplitter

a simpler interface, where only the gain of a split is defined.

RuleTree.stumps.Stump.Stump

the stump that combines a transformer and a splitter.

Examples

A splitter that splits the first numerical feature at its median (see Extending the library):

>>> import numpy as np
>>> from RuleTree.base.RuleTreeBaseSplitter import RuleTreeBaseSplitter
>>> from RuleTree.utils.define import MODEL_TYPE_REG
>>> class MedianSplitter(RuleTreeBaseSplitter):
...     task = MODEL_TYPE_REG
...
...     def fit(self, X, y, numerical, categorical, sample_weight=None, check_input=True):
...         self.feature_ = numerical[0]
...         self.threshold_ = float(np.median(X[:, self.feature_]))
...         self.is_categorical_, self.gain_, self.impurity_ = False, 0.0, None
...         return self
>>> X = np.array([[1.0], [2.0], [3.0], [4.0]])
>>> MedianSplitter().fit(X, None, numerical=[0], categorical=[]).apply(X)
array([1, 1, 2, 2])

set_fit_request(*, categorical: bool | None | str = '$UNCHANGED$', check_input: bool | None | str = '$UNCHANGED$', numerical: bool | None | str = '$UNCHANGED$', sample_weight: bool | None | str = '$UNCHANGED$') → RuleTreeBaseSplitter#

Configure whether metadata should be requested to be passed to the fit method.

Note that this method is only relevant when this estimator is used as a sub-estimator within a meta-estimator and metadata routing is enabled with enable_metadata_routing=True (see sklearn.set_config()). Please check the User Guide on how the routing mechanism works.

The options for each parameter are:

  • True: metadata is requested, and passed to fit if provided. The request is ignored if metadata is not provided.

  • False: metadata is not requested and the meta-estimator will not pass it to fit.

  • None: metadata is not requested, and the meta-estimator will raise an error if the user provides it.

  • str: metadata should be passed to the meta-estimator with this given alias instead of the original name.

The default (sklearn.utils.metadata_routing.UNCHANGED) retains the existing request. This allows you to change the request for some parameters and not others.

Added in version 1.3.

Parameters:

  • categorical (str, True, False, or None, default=sklearn.utils.metadata_routing.UNCHANGED) – Metadata routing for categorical parameter in fit.

  • check_input (str, True, False, or None, default=sklearn.utils.metadata_routing.UNCHANGED) – Metadata routing for check_input parameter in fit.

  • numerical (str, True, False, or None, default=sklearn.utils.metadata_routing.UNCHANGED) – Metadata routing for numerical parameter in fit.

  • sample_weight (str, True, False, or None, default=sklearn.utils.metadata_routing.UNCHANGED) – Metadata routing for sample_weight parameter in fit.
